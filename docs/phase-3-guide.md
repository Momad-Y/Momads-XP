## 1. Phase summary

**Goal (§9):** CMD, Python, Paint, Music Player — the "power user" experience.
**Exit criteria:** all four functional and styled authentically.

| App | What shipped |
| --- | --- |

## 2. Required assets

Everything needed is committed. Two things a future maintainer may want to
replace:

**Music.** `static/audio/music/{ascent,pulse,drift}.mp3` are generated by
`scripts/gen-tracks.sh` (ffmpeg + libmp3lame). To ship real music instead: drop
files into `static/audio/music/` and update `src/lib/music/manifest.ts`
(`filename`, `url`, `size_kb`, `duration_s`). A test asserts `size_kb` matches
the committed bytes, so a wrong number is a red test rather than a wrong
Explorer column.

> **Local files only.** A cross-origin URL makes a
> `MediaElementAudioSourceNode` output **silence** into the graph — playback
> still works, the analyser reads zeros, and the visualiser dies with nothing
> but a console warning.

> **Track ids are permanent.** `merge_on_reseed` carries any cached item absent
> from a later seed and there is no mechanism to reap one, so a renamed id
> persists in every returning visitor's `My Music` forever, beside its
> replacement.

**Icons.** All in the shipped set; none were added.
`Python.png` and `WindowsMediaPlayer9.png` already existed and were simply
unused — the Start Menu had been passing the generic `ApplicationWindow.png`.

## 3. Setup & commands

Node 22 (CI) / npm 10 for lockfiles. Local toolchain may be newer; see §5.

```bash
npm ci
npm run dev            # http://localhost:3000
npm run build          # production
npm run preview        # http://localhost:4173
npm run generate:vfs   # after ANY profile.json or manifest change
bash scripts/gen-tracks.sh    # only to regenerate the audio (needs ffmpeg)
node scripts/prune-jspaint.mjs  # idempotent; re-run after re-vendoring jspaint
```

Gate chain before any push:

```bash
npm run check && npm run lint && npm run format:check \
  && npx vitest run --coverage \
  && diff-cover coverage/lcov.info --compare-branch origin/dev --fail-under 80 \
  && npm run build \
  && node scripts/verify-build.mjs /tmp/build.log \
  && npx playwright test --project=default
```

**Fetch before diff-cover.** Comparing against a stale `origin/dev` reports
"no lines with coverage information" and hides a failing gate — that happened
twice in this phase.

**Playwright projects are explicit.** `default` is hermetic; `online` runs real
Pyodide and is excluded:

```bash
npx playwright test --project=default   # what CI runs
npx playwright test --project=online    # ~5 MB from jsDelivr, run deliberately
```

## 6. profile.json dependencies

CMD reads these. Note there is **no runtime validation** — `profile.ts`
deliberately declines a schema, so a missing field is a compile error while an
*empty* array (`social`, `skills`, `bio`) renders as silent blank output:

| Field | Used by |
| --- | --- |
| `meta.name`, `meta.title` | `about` |
| `meta.shortName` | `whoami` (lowercased), `sudo` |
| `meta.email`, `meta.location` | `contact` |
| `about.bio` (array of paragraphs) | `about` |
| `skills` (group → string[]) | `skills` |
| `experience[]` `.role/.company/.period/.location/.description[]` | `experience` |
| `projects[]` `.name/.description/.tech[]` | `projects` |

| `systemProperties.general.system/.computer` | `uname -a` |

## 7. Deployment (Netlify)

Unchanged from `phase-2-guide.md` — auto-builds stay **off**, deploys are
prebuilt from the CLI:

```bash
npm run build && npx netlify deploy --prod --dir=build --no-build \
  --site 73331ef4-01f7-4fc4-9848-f22261cc9dab
```

No new functions, so no new invocation cost. Two things that *are* new:

- **Third-party traffic and privacy.** Opening Python fetches ~5 MB from
  `cdn.jsdelivr.net`, which sees the visitor's IP and User-Agent. Nothing else
  in the product does this. Disclose it if a privacy note is ever added.
- **Deploy size.** `static/` net *shrank*: jspaint 45 MB → 21 MB, audio +1.1 MB.

## 9. Visual parity report

Screenshots at **1280×800**, in `design/research/`:
`phase3-cmd.png`, `phase3-python.png`, `phase3-paint.png`,
`phase3-music-player.png`.

**What is scored, and what is not.** §11 distinguishes inherited surfaces
("do not regress") from new ones ("compare against the closest reference").
Two of these surfaces have no XP original at all — §3.2 specifies CMD as a
*Linux-style* terminal titled `momad@xp:~`, which Windows XP never had, and
there is no XP Python REPL. So parity is scored on **the XP window chrome and
each app's own layout**, and jspaint's interior is **explicitly not scored** —
it runs its own `classic.css` theme (`paint.svelte:241`), and reporting a
number for a vendored interior we do not control would be a fabricated
measurement.

| Surface | Scored against | Result |
| --- | --- | --- |
| CMD | XP window chrome + taskbar; §3.2's palette and title | Title bar, icon, buttons and taskbar button indistinguishable from inherited windows. Grey-white `#c0c0c0` body on black with a green prompt |
| Python | Same chrome; content vs a real CPython transcript | Chrome identical to CMD. Banner and `>>>` match a real REPL |
| Paint | XP window chrome only | Chrome correct; full §3.2 tool set, palette, menus and status bar present after the prune. **Interior not scored** — documented deviation |
| Music Player | WMP 9 layout | Visualiser, transport, seek, volume and track list laid out as WMP 9. XP chrome correct |

**Two defects the loop caught**, which is what §11 says it is for:

1. **The Python banner staircased.** It is multi-line, and writing it as one
   string left bare `\n` in the stream — xterm does not translate those, so the
   second line began wherever the first ended. Now split and written per line.
2. **The visualiser lit only ~4 bars of 28.** An FFT's bins are linear in
   frequency while musical energy sits in the bottom few percent, so a linear
   bin mapping left most of the widget dark and it read as broken. Bins are now
   **log-spaced**, as a real spectrum analyser does.

**No pixel-diff number is reported, deliberately.** The repo has no
`toHaveScreenshot`, `pixelmatch` or equivalent, and two of the four surfaces
have no reference image to diff against. §11 forbids eyeballing and moving on —
so the evidence is the four committed screenshots and the per-surface findings
above, not a percentage that was never measured.

## 10. Notes & gotchas

**A module worker cannot be constructed from an opaque origin.** Measured in a
real `sandbox="allow-scripts"` frame (`blob:null/…`): a classic blob worker
works, a **module** blob worker fails with an opaque error and no message, and
so does `import()` of `pyodide.mjs` from one. `importScripts` of the UMD
`pyodide.js` works. **This makes the Pyodide pin architectural** — 314.x drops
classic worker support entirely, so upgrading past 0.28.x breaks the isolation
model, not merely the banner text. A test guards the `importScripts` shape.

**§3.2's "Python 3.13.x" is a consequence of the pin**, not an independent
requirement. `latest` is 314.0.5 → Python 3.14.2.

**Never add `script-src` to `netlify.toml`'s `/*` block.** It would block
jQuery UI (the window manager), `loadjs`, SvelteKit's inline hydration
bootstrap, and the reporter injected into every `/api/browse` response — a
white screen on the deploy that **no local gate can see**, because
`vite preview` does not apply the file.

**Netlify merges header rules by NAME, and the LAST matching rule wins — not
the most specific one.** This is not a footnote; it silently disabled the
phase's headline security control for a while. The sandbox CSP block was
declared *before* `/html/*`, whose
`Content-Security-Policy = "frame-ancestors 'self'"` then overwrote the whole
policy, so the page shipped with no `script-src`, no `worker-src` and no
`connect-src`. Measured with `netlify dev --dir build`:

```
before:  Content-Security-Policy: frame-ancestors 'self'
after:   Content-Security-Policy: default-src 'none'; script-src ...
```

The sandbox block is therefore **last** in the file, and must stay last.

**`store.subscribe()` fires synchronously.** `work_space` can initialise with a
program already queued, so anything `launch()` touches must be declared **above**
the subscription. Getting this wrong produced
`Cannot access 'singleton_programs' before initialization` and broke boot.

**`createMediaElementSource()` is a permanent one-shot binding on the element**
— a second call throws `InvalidStateError` even from a different
`AudioContext`. Cached in a `WeakMap`. And `await ctx.resume()` outside a user
gesture **never settles**, so `resume()` is called synchronously first.

**xterm consumes Escape** on its own textarea, so a terminal cannot be used to
test window-level Escape handling. A terminal-based version of the Dialog
focus test passed *with the guard removed*.

**`PyodideConsole.push()` keeps its OWN buffer.** Send it ONE line at a time.
Sending the accumulated block double-concatenates (`self.buffer.append(line);
source = "\n".join(self.buffer)`), so every `def`/`if`/`for` raised
`IndentationError` and the function was never defined. It shipped that way
because the only real-execution test typed `2 + 2`; there is now an `@online`
test that runs a real `def` block.

**`location.reload()` is not accessible on an opaque-origin frame.** Reading it
throws `SecurityError`. Use the `href` **setter**, which *is* cross-origin
permitted. The Ctrl+C restart shipped broken for the same reason the
continuation bug did — the unit test injected a `reload: vi.fn()` stub and
measured it, and there was no `@online` test at all. Both now exist.

**`input()` is not supported.** A blocking read across the worker boundary needs
`SharedArrayBuffer` + COOP/COEP, which §5 records as breaking other embeds
here. JSPI could do it without cross-origin isolation, but it is experimental
and absent from Safari stable. Ctrl+C is likewise a **restart**, not an
interrupt — `setInterruptBuffer` needs `SharedArrayBuffer` too — and the UI
says `Restarting Python… (session state cleared)`.

**The second `.mp3` handler surfaces on one path only.** `CMFSItem` renders
"Open With" when there are ≥2 handlers, but `viewer.svelte`,
`desktop_folder.svelte` and `favorites.ts` all take `doctypes[0]`
unconditionally — so File ▸ Open never shows it. Asserted by unit test; the
e2e for it was dropped after the row locator proved unstable across the Details
re-render (a flaky test is worse than a stated gap).

The player now **honours the file it was opened with** (`fs_item` → matching
track). Until gate 6 it discarded the payload and always played track 0, which
made the whole reason for the second `doctypes` entry a no-op.

**Registry apps must receive `options.id`.** `Window.svelte` needs it for three
separate things — `program-id` (so `click_outside` can exclude the window's own
taskbar tile), the minimize animation target, and `calc_nudges`' sibling
comparison. Omitting it silently broke all three for the new apps only, and two
Command Prompts opened at *identical* coordinates.

**jspaint after the prune.** `sessions.js` is **kept** — it defines
`window.new_local_session`, called unguarded from `functions.js:805`/`:923`, so
deleting it breaks every image open. Only the `#load:`/`#session:` router and
the Firebase session were removed. The file deletions are an **explicit
allowlist**: `index.html` references `styles/themes` zero times (the theme is
built by runtime string construction), so "prune to what index.html loads"
deletes the only stylesheet Paint has. `verify-build.mjs` asserts
`classic.css` survives.

**The Paint sandbox disables some jspaint paths.** `allow-scripts
allow-same-origin` is required (the wrapper reads `contentDocument` and
`systemHooks`), and it removes top-navigation, popups, forms, modals and
downloads. So jspaint's own `saveAs` downloads, its `alert()` fallbacks and its
`target="_blank"` help links are inert. Save As into the VFS is unaffected — it
goes through our wrapper. **About Paint's update check is REMOVED.** An earlier version of this guide
called it "a Help-menu action, not an automatic fetch" and disclosed it instead.
Both halves were wrong: opening About fetched `https://jspaint.app`
automatically, and the "What's New?" button appended that remote HTML into the
live jspaint document with jQuery — whose `.append()` extracts and
`globalEval`s any `<script>` in it, on our real origin. It also re-imported the
very `i.postimg.cc` images the first prune deleted.

**Two more third-party paths the first prune missed**, both now closed:
`load_image_from_uri` fanned out to `cors.bridged.cc` and
`jspaint-cors-proxy.herokuapp.com` (a retired free Heroku dyno, i.e.
re-registrable) — reachable not via `#load:` but via the **paste handler**, so
pasting any URL into Paint sent it and the visitor's IP to third parties. And
396 KB of orphaned Firebase SDK plus `electron-injected.js` were still
directly linkable under `/html/`.

**Known limitations**

- **≥1024 px touch devices** get the full desktop (§4.6), and the terminals
  have no on-screen-keyboard or Ctrl+C story there. Phase 6 owns touch polish.
- Portrait mobile is unaffected: §4.6 renders a static page with no window
  management and explicitly forbids loading xterm.js or Pyodide.
- `Dialog.svelte` is still both statically and dynamically imported by nine
  modules, so it is never code-split. Inherited; baselined in
  `verify-build.mjs` rather than fixed inside a feature phase.
- The registry and the inherited if-chain coexist until Phase 6.
